> **ПРЕДУПРЕЖДЕНИЕ**
> Этот репозиторий содержит систему распознавания документов. Модуль `generator` создаёт синтетические изображения с несуществующими данными для тестирования и демонстрации. Каждое сгенерированное изображение содержит крупный водяной знак «ОБРАЗЕЦ» и не является действительным документом. Проект не предназначен для создания подделок, обхода KYC или любой незаконной деятельности. Используйте на свой страх и риск.

**I-DOC** — это экосистема распознавания документов, предназначенная для извлечения и обработки данных машиночитаемой зоны (MRZ) внутренних паспортов РФ. Проект состоит из трёх независимых модулей, объединённых в монорепозиторий.

## Модули

*   **`backend/`** — REST API на базе FastAPI. Принимает изображения, извлекает текст с помощью OCR (OmniMRZ) и применяет кастомные правила парсинга в зависимости от типа документа.
*   **`mobile/`** — Кроссплатформенное мобильное приложение на React Native (Expo). Обеспечивает интерфейс для авторизации, сканирования документов и отображения результатов.
*   **`generator/`** — Python-скрипт для генерации синтетических тестовых данных. Создаёт изображения паспортов с валидными контрольными цифрами, водяными знаками и визуальным шумом для симуляции реальных условий.

## Особенности реализации

*   **Алгоритмы MRZ:** Реализована точная посимвольная транслитерация по схеме «модернизированный клер» и расчёт контрольных цифр по стандарту 7-3-1 в строгом соответствии с Приказом МВД № 773 (Приложение 24) для внутренних паспортов РФ.
*   **Расширяемая архитектура (паттерн «Стратегия»):** Логика парсинга построена на абстрактном базовом классе `MRZRuleSet`. Это позволяет легко подменять или добавлять правила для разных типов документов (например, для загранпаспортов) без изменения существующего кода.
*   **Безопасность:** JWT-аутентификация с разделением ролей. Первичный администратор создаётся через переменные окружения при старте сервера для предотвращения несанкционированной регистрации.
*   **Генерация данных:** Скрипт накладывает валидный MRZ-текст на шаблон, добавляя шум и размытие для симуляции условий съёмки на камеру смартфона (тестирование устойчивости OCR к зашумлённым изображениям).

## Стек технологий

*   **Mobile:** React Native, Expo, React Navigation, React Native Paper.
*   **Backend:** Python, FastAPI, SQLAlchemy (SQLite), PyJWT, Passlib (bcrypt), OmniMRZ.
*   **Generator:** Python, PIL (Pillow), NumPy.

## Запуск проекта

### Бэкенд
```bash
cd backend
python -m venv venv
# Windows: venv\Scripts\activate
# Mac/Linux: source venv/bin/activate
pip install -r requirements.txt
```

*Примечание: для создания первого администратора задайте переменные окружения `ADMIN_USERNAME` и `ADMIN_PASSWORD` перед запуском.*

**Windows (PowerShell):**
```powershell
$env:ADMIN_USERNAME="admin"; $env:ADMIN_PASSWORD="yourpassword"; uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

**Linux / macOS:**
```bash
ADMIN_USERNAME=admin ADMIN_PASSWORD=yourpassword uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

### Мобильное приложение

**Для локальной разработки:**
```bash
cd mobile
npm install
npm start
```

**Для сборки APK (для тестирования на реальном устройстве):**
Убедитесь, что у вас установлен EAS CLI и вы авторизованы:
```bash
npm install -g eas-cli
eas login
```

Так как бэкенд запускается локально, приложению нужно знать ваш локальный IP-адрес. Сохраните его в переменные окружения вашего проекта EAS:
```bash
eas env:set --name EXPO_PUBLIC_BACKEND_URL --value "http://ВАШ_ЛОКАЛЬНЫЙ_IP:8000" --environment preview --visibility plaintext
```
*(Замените `ВАШ_ЛОКАЛЬНЫЙ_IP` на IP вашего компьютера, например, `192.168.1.42`)*

Затем запустите сборку:
```bash
eas build --profile preview --platform android
```

### Генератор
```bash
cd generator
pip install -r requirements.txt
python generator.py
```
*Сгенерированные изображения сохраняются в папку `output/`.*
